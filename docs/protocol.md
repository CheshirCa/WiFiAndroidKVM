# Сетевой протокол

TCP-ввод использует `5556/TCP`. Агент слушает `0.0.0.0:5556`; первый пакет каждого соединения — обязательный `AUTH` с ключом `KVM2026`, который должен полностью поступить за пять секунд. TCP остаётся потоком, поэтому агент накапливает данные до полного пакета. После AUTH ядро TCP применяет keepalive (простой 5 секунд, три проверки по 2 секунды) для освобождения слота пропавшего клиента. Формат ввода не изменён discovery.

Все TCP-пакеты имеют длину 8 байт. `int16` передаются little-endian.

| Type | Имя | Payload |
|---:|---|---|
| `0x01` | MOVE | Байты 1–2: `int16 dx`; 3–4: `int16 dy`. |
| `0x02` | BUTTON | Байт 1: 1 — левая, 2 — правая, 3 — средняя; байт 2: 0 — отпускание, 1 — нажатие. |
| `0x03` | WHEEL | Байты 1–2: `int16 delta`; положительное значение прокручивает вверх. |
| `0x04` | KEY | Байты 1–2: `uint16` Linux input key code; байт 3: 0 — отпускание, 1 — нажатие. |
| `0x7d` | AUTH | Только первым пакетом: байты 1–7 — ASCII `KVM2026`. |
| `0x7e` | PING | Нет данных. |
| `0x7f` | DISCONNECT | Агент освобождает кнопки и закрывает соединение. |

Остальные байты равны нулю. При разрыве TCP агент освобождает левую, правую и среднюю кнопки, а также все виртуально нажатые клавиши. Для `KEY` принимаются только коды, передаваемые Windows-клиентом: основной набор до F12, клавиши дополнительной клавиатуры и навигации, правые Ctrl/Alt и Win; `KEY_POWER`, `KEY_SLEEP`, `KEY_WAKEUP` и `BTN_*` отклоняются. В ручном режиме `--right-button-back` вместо правой освобождается `KEY_BACK`; этот режим нельзя использовать вместе с Xtralogic RDP.

`KVM2026` — фиксированный общий секрет текущей версии, который передаётся без шифрования. Агент предназначен только для доверенной LAN; индивидуальный секрет и HMAC потребуют изменения протокола и Windows-клиента.

## Обнаружение в LAN

Discovery использует `5557/UDP` и не заменяет TCP. Windows отправляет точный ASCII-запрос `WAKVM_DISCOVER_1` на направленные IPv4 Broadcast адреса активных адаптеров и дополнительно на `255.255.255.255`. Агент отвечает UDP Unicast с исходного адреса запроса.

Ответ имеет ASCII-формат `WAKVM_REPLY_1|<name>|<ip>|<tcp-port>|1`. Поле `<ip>` служит справкой; Windows использует адрес источника UDP-пакета для подключения. В broadcast и ответ не передаются ключ TCP-авторизации или команды ввода. Неподходящие и дублирующиеся ответы игнорируются.

Поиск занимает около двух секунд и запускается только при старте клиента или по кнопке «Найти устройства». Он не выполняется непрерывно в фоне. Если UDP Broadcast запрещён сетью, подключайтесь через ручной IP/DNS и TCP-порт.
